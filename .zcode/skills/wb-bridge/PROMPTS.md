# PROMPTS — worker 提示词模板体系（v4）

> 本文件是 wbx 桥的 **worker 提示词模板库**，由 [SKILL.md](SKILL.md) 引用。v4 核心变化：
> 外包判定从「轻量文本活」升级为「**自包含任务**」——全部输入（含代码上下文）可由编排器
> 打包进提示词、输出可独立校验即可外包，因此新增**代码模块编写模板**并升级既有五类模板。
> 写法吸收 DeepSeek 官方提示库与思考模式/JSON 输出指南的建议
> （来源见 WBX.md v4 章「调研记录」）。

## 通用原则（所有模板共用）

1. **四段式结构**：角色 → 任务一句话 → 【输入材料】→ 【输出要求】。指令全部写进这一条
   用户消息（worker 是无工具的纯文本端点，没有对话历史）。
2. **无工具声明必写**：「你没有任何工具，不能联网、不能读写文件，仅凭下面给定的材料作答」
   ——防幻觉、防它假装去查资料。
3. **输出硬约束收尾**：只输出什么、不要什么（解释/前后缀/客套话/围栏）、不确定怎么办
   （UNKNOWN / null / `// TODO(原因)`，绝不编造）。
4. **材料先行**：worker 看不到你的会话上下文，凡是它需要知道的（代码、日志、原文、接口定义）
   都要**完整贴进【输入材料】区**。fanout 任务可用 `"files": ["路径"]` 让桥代读文件拼接
   （v4 起；相对路径基于 tasks.json 所在目录）。
5. **材料裁剪准则**：单任务材料超 **20k 字符**时，贴「接口定义（类型/签名/export 段）+
   关键实现段」，并在材料段首注明「已裁剪：仅保留接口与关键段」；不要无声截断。
   长度上限：v4 起桥对 >12000 字符的提示词自动走 stdin 通道（实测 60k+ 字符可用），
   但材料越长费用/延迟越高，仍应按需裁剪。
6. **JSON 任务给骨架**：提示词中必须出现 "JSON" 字样并给出目标格式样例
   （DeepSeek 官方 json_mode 指南要求），字段语义逐行说明，缺省值写明（null / UNKNOWN）。
7. **effort 档位**（`minimal / low / medium / high / xhigh / max`）：简单文本任务 `low`；
   代码模块与多约束任务 `medium`；不确定就不传（模型默认档）。
8. **校验后才使用**：模板只是提高一次通过率；产物必须经 ZCode 审查/运行后才进交付物
   （铁律，见 SKILL.md）。

## 模板速查

| 模板 | 适用 | effort 建议 |
|---|---|---|

## T1 代码模块编写（核心新增）

**适用判定**（全部满足才分派）：单文件可承载的模块/组件/纯函数；接口由 ZCode 定义清楚；
所需的上下文（类型、依赖、风格样例）可以贴进材料；输出可独立校验（编译/运行/审查）。
ZCode 负责：接口定义、集成、审查；worker 只负责按契约写实现——**派发结果不派发步骤**。

```
你是一名{语言/框架/领域}资深工程师。任务：实现 {模块名/文件名} 这一个文件。
你没有任何工具，不能联网、不能读写文件、不能执行代码，仅凭下面的契约与材料作答。

【接口契约】
- 文件：{目标路径与文件名}
- 导出：{函数/类/常量签名，含参数名、类型、返回值类型}
- 调用约定：{如何被调用；错误如何报告（抛异常/返回 null/Result）；同步或异步}
- 依赖：{允许使用的库与版本边界；零依赖则写「仅标准库」或「仅 Node 内置模块」}
- 验收标准：{可判定的行为，例：给定输入 X 返回 Y；非法输入返回 null 不抛异常；…}

【输入材料】
{相关文件全文；超 20k 字符时改为：接口定义段 + 关键实现段，并在此注明
「已裁剪：仅保留接口与关键段」}

【输出要求】
- 只输出一份完整代码，包在 ```{语言} 围栏中，无任何解释、前后缀或客套话
- 代码完整可编译/可解析：不省略 import，不写 "…" 省略体，不改动契约中已定义的签名
- 遇到材料未覆盖、无法确定的细节：以注释 {该语言的 TODO 语法} 标注 TODO(原因) 占位，
  绝不编造 API、字段名或行为
- 风格：{缩进/引号/命名约定；遵循材料中现有代码风格}
```

### T1 填好的示例

```
你是一名 Node.js (CommonJS) 资深工程师。任务：实现 lib/parse-duration.js 这一个文件。
你没有任何工具，不能联网、不能读写文件、不能执行代码，仅凭下面的契约与材料作答。

【接口契约】
- 文件：lib/parse-duration.js
- 导出：module.exports = function parseDuration(input) ，输入 string，输出 number（毫秒）或 null
- 调用约定：同步纯函数；无法解析时返回 null，绝不抛异常；空串/非字符串返回 null
- 依赖：仅 Node 内置模块（本模块实际不需要任何 require）
- 验收标准：
  1. parseDuration("1h30m") === 5400000
  2. parseDuration("500ms") === 500
  3. parseDuration("2d") === 172800000
  4. parseDuration("1.5h") === 5400000
  5. parseDuration("") === null；parseDuration("abc") === null
  6. 支持单位：ms、s、m、h、d（大小写不敏感），可连写（如 "1h30m20s"），可含小数

【输入材料】
同项目 lib/slugify.js（风格样例，导出与 JSDoc 风格照此）：
----- 文件 lib/slugify.js 开始 -----
"use strict";

/**
 * 把任意文本转成 URL 安全的 slug。
 * @param {string} input
 * @returns {string|null} 无法处理时返回 null
 */
module.exports = function slugify(input) {
  if (typeof input !== "string" || !input.trim()) return null;
  return input.trim().toLowerCase().replace(/[^a-z0-9]+/g, "-").replace(/^-+|-+$/g, "");
};
----- 文件 lib/slugify.js 结束 -----

【输出要求】
- 只输出一份完整代码，包在 ```js 围栏中，无任何解释、前后缀或客套话
- 代码完整可解析：无省略体，使用 "use strict" 与 JSDoc，风格与样例一致
- 遇到材料未覆盖的细节：用 // TODO(原因) 标注，绝不编造
```

## 代码任务分派流程（编排器视角）

1. **拆分**：ZCode 把一段工作拆成模块，接口清晰的模块才可外包；ZCode 先写好接口契约
   （签名、类型、错误约定、验收标准）。
2. **备料**：读相关文件；用 T1 模板组装提示词（材料全文或按裁剪准则裁剪）；
   fanout 任务可直接写 `"files": [...]` 让桥拼材料。
3. **分派**：≤3 个任务用 `ask --file`，≥3 个用 `fanout`；effort 建议 medium。
4. **校验**：逐份审查输出——围栏外有没有夹带、是否完整、有没有编造的 API 或 TODO；
   保存为文件后编译/运行验收（集成、修 bug 由 ZCode 做，**每文件单一写者**：落盘后该文件归 ZCode 管）。
5. **止损**：连续 ≥2 个任务失败或限流 → 停止外包，剩余自己写（见 SKILL.md 失败降级规则）。
