# PROMPTS — worker 提示词知识库（v2）

> 本文件是 wbx 桥的 **worker 提示词模板库与经验知识库**，由 [SKILL.md](SKILL.md) 引用。v4 核心：
> 外包判定从「轻量文本活」升级为「**自包含任务**」——全部输入（含代码上下文）可由编排器
> 打包进提示词、输出可独立校验即可外包，因此新增**代码模块编写模板**并升级既有五类模板。
> v2（v5）核心：知识**可复用、可判定、可增量**——原则增至 12 条、模板扩到 9 类（+评审批判/
> best-of-N/修复迭代）、新增**经验条目库**（E-xxx，带来源）与**沉淀闭环**（history → 复盘 → 入库）。
> 写法吸收 DeepSeek 官方提示库与思考模式/JSON 输出指南的建议（来源见 WBX.md v4 章「调研记录」）。

## 通用原则（所有模板共用）

1. **四段式结构**：角色 → 任务一句话 → 【输入材料】→ 【输出要求】。指令全部写进这一条
   用户消息（worker 是无工具的纯文本端点，没有对话历史）。
2. **无工具声明必写**：「你没有任何工具，不能联网、不能读写文件，仅凭下面给定的材料作答」
   ——防幻觉、防它假装去查资料。
3. **输出硬约束收尾**：只输出什么、不要什么（解释/前后缀/客套话/围栏）、不确定怎么办
   （UNKNOWN / null / `// TODO(原因)`，绝不编造）。
4. **材料先行**：worker 看不到你的会话上下文，凡是它需要知道的（代码、日志、原文、接口定义）
   都要**完整贴进【输入材料】区**。fanout 任务可用 `"files": ["路径"]` 让桥代读文件拼接
   （v4 起；相对路径基于 tasks.json 所在目录）。
5. **材料裁剪准则**：单任务材料超 **20k 字符**时，贴「接口定义（类型/签名/export 段）+
   关键实现段」，并在材料段首注明「已裁剪：仅保留接口与关键段」；不要无声截断。
   长度上限：v4 起桥对 >12000 字符的提示词自动走 stdin 通道（实测 60k+ 字符可用），
   但材料越长费用/延迟越高，仍应按需裁剪。**v5 语义修正：裁剪只为信噪比（质量），不为省钱**
   ——三 lane 几乎免费，材料给足；20k 准则继续用于控制信噪比与延迟。
6. **JSON 任务给骨架**：提示词中必须出现 "JSON" 字样并给出目标格式样例
   （DeepSeek 官方 json_mode 指南要求），字段语义逐行说明，缺省值写明（null / UNKNOWN）。
7. **effort 档位**（`minimal / low / medium / high / xhigh / max`）：简单文本任务 `low`；
   代码模块与多约束任务 `medium`；不确定就不传（模型默认档）。
   **v5 上调**（消耗豁免，实测延迟可接受为前提）：简单任务 low→medium、代码 medium→high；
   若延迟明显变长再回调。cline lane 不适用（思考档固定取 config，任务级 effort 忽略）。
8. **校验后才使用**：模板只是提高一次通过率；产物必须经 ZCode 审查/运行后才进交付物
   （铁律，见 SKILL.md）。
9. **产物形态先行**（P9）：第一句话说清「要什么 + 边界在哪」（官方代码生成样例即此写法：
   「生成五子棋游戏，所有代码保存在一个 HTML 中」）。派发前先自问：交付物长什么样、
   装在哪个文件、一句话能描述完吗。
10. **JSON 三件套**（P10）：① 提示词里出现 "JSON" 字样；② 给完整骨架 + 逐字段一行语义；
    ③ 设置合理的 max_tokens 防截断。缺一件都会劣化（字段漂移 / 截断成非法 JSON）。
11. **思考档位按复杂度取舍**（P11）：复杂推理/多约束任务开思考、简单任务调低省延迟
    （官方思考模式指南）；不传档位则用模型默认。
12. **上下文边界声明**（P12）：思维链（reasoning_content）**不进上下文**——不要假设模型
    「记得」上一步推理；每次派发都是全新会话，需要它知道的结论必须写进材料。

## T1 代码模块编写（核心新增）

**适用判定**（全部满足才分派）：单文件可承载的模块/组件/纯函数；接口由 ZCode 定义清楚；
所需的上下文（类型、依赖、风格样例）可以贴进材料；输出可独立校验（编译/运行/审查）。
ZCode 负责：接口定义、集成、审查；worker 只负责按契约写实现——**派发结果不派发步骤**。

```
你是一名{语言/框架/领域}资深工程师。任务：实现 {模块名/文件名} 这一个文件。
你没有任何工具，不能联网、不能读写文件、不能执行代码，仅凭下面的契约与材料作答。

【接口契约】
- 文件：{目标路径与文件名}
- 导出：{函数/类/常量签名，含参数名、类型、返回值类型}
- 调用约定：{如何被调用；错误如何报告（抛异常/返回 null/Result）；同步或异步}
- 依赖：{允许使用的库与版本边界；零依赖则写「仅标准库」或「仅 Node 内置模块」}
- 验收标准：{可判定的行为，例：给定输入 X 返回 Y；非法输入返回 null 不抛异常；…}

【输入材料】
{相关文件全文；超 20k 字符时改为：接口定义段 + 关键实现段，并在此注明
「已裁剪：仅保留接口与关键段」}

【输出要求】
- 只输出一份完整代码，包在 ```{语言} 围栏中，无任何解释、前后缀或客套话
- 代码完整可编译/可解析：不省略 import，不写 "…" 省略体，不改动契约中已定义的签名
- 遇到材料未覆盖、无法确定的细节：以注释 {该语言的 TODO 语法} 标注 TODO(原因) 占位，
  绝不编造 API、字段名或行为
- 风格：{缩进/引号/命名约定；遵循材料中现有代码风格}
```

### T1 填好的示例

```
你是一名 Node.js (CommonJS) 资深工程师。任务：实现 lib/parse-duration.js 这一个文件。
你没有任何工具，不能联网、不能读写文件、不能执行代码，仅凭下面的契约与材料作答。

【接口契约】
- 文件：lib/parse-duration.js
- 导出：module.exports = function parseDuration(input) ，输入 string，输出 number（毫秒）或 null
- 调用约定：同步纯函数；无法解析时返回 null，绝不抛异常；空串/非字符串返回 null
- 依赖：仅 Node 内置模块（本模块实际不需要任何 require）
- 验收标准：
  1. parseDuration("1h30m") === 5400000
  2. parseDuration("500ms") === 500
  3. parseDuration("2d") === 172800000
  4. parseDuration("1.5h") === 5400000
  5. parseDuration("") === null；parseDuration("abc") === null
  6. 支持单位：ms、s、m、h、d（大小写不敏感），可连写（如 "1h30m20s"），可含小数

【输入材料】
同项目 lib/slugify.js（风格样例，导出与 JSDoc 风格照此）：
----- 文件 lib/slugify.js 开始 -----
"use strict";

/**
 * 把任意文本转成 URL 安全的 slug。
 * @param {string} input
 * @returns {string|null} 无法处理时返回 null
 */
module.exports = function slugify(input) {
  if (typeof input !== "string" || !input.trim()) return null;
  return input.trim().toLowerCase().replace(/[^a-z0-9]+/g, "-").replace(/^-+|-+$/g, "");
};
----- 文件 lib/slugify.js 结束 -----

【输出要求】
- 只输出一份完整代码，包在 ```js 围栏中，无任何解释、前后缀或客套话
- 代码完整可解析：无省略体，使用 "use strict" 与 JSDoc，风格与样例一致
- 遇到材料未覆盖的细节：用 // TODO(原因) 标注，绝不编造
```

## T7 评审批判

**定位**：接在外包产物的校验环节之后；多一次免费调用换质量下限（v5 起从例外变常规）。

**适用判定**（编排器视角，满足任一即分派）：
- 代码模块集成前**默认触发**，无需额外理由；
- 关键文案/方案定稿前可触发；
- 单行/纯文档/注释改动可跳过——跳过须在评审记录写一行 skip 理由；
- best-of-N（T8）择优后必走。

```
你是一名{语言/领域}资深评审工程师。任务：审查下面这一份{代码/文案/方案}产物，只输出问题清单。
你没有任何工具，不能联网、不能读写文件、不能执行代码，仅凭下面的契约与材料作答。

【评审契约】
- 被审对象：{文件路径或文档名}
- 验收标准：{逐条，与产出时的契约一致}
- 严重度定义：阻断＝违反验收标准或会导致错误结果，必须修；建议＝不违反验收但影响质量
- 评审范围：{默认全文；或指定章节}

【待审产物全文】
{产物全文；核心逻辑不得裁剪。超 20k 字符时改为关键段并注明「已裁剪：仅保留核心逻辑段」}

【实现者自述取舍】（可选；无则写「无」）
{实现者说明设计取舍与已知权衡}

【输出要求（硬约束）】
- 只输出问题清单，每条为固定四元组，格式：
  位置 → 问题 → 严重度[阻断|建议] → 最小修复
  · 位置：{文件:行号 / 函数名 / 章节}；无法定位写 UNKNOWN
  · 问题：一句话说清违反了哪条验收或哪里会出错

- **关联**：原则 P8；模板 T7/T9

### E-008 契约未覆盖的行为：TODO 占位，不猜测
- **来源**：实测（WBX.md v4 章 Phase 5.1：外包 3 模块对空白字符、Infinity、TB 封顶、
  日期取值合法性等契约外行为全部 `// TODO(原因)` 标注，零编造，三份产物零返工）
- **适用场景**：T1/T9 代码任务的契约设计
- **要点**：契约写「不确定处 TODO(原因) 占位、绝不编造」这一句，worker 就真的会守住边界；
  回收后由 ZCode 逐条决断补齐。
- **反例**：契约里不写这句，worker 会对未定义行为自行发挥（编造 API/字段）。
- **关联**：原则 P3；模板 T1/T9

### E-009 连续 ≥2 失败即止损，不做无限重试
- **来源**：实测（v2 起冻结铁律；2026-09-25 job 20260925-115826-idp 的 auth 误判案例：
  单任务重试+跨 lane 共 3 次尝试全部浪费在误判上）
- **适用场景**：fanout/ask 的失败处理
- **要点**：连续 ≥2 个任务失败、或错误含 quota/429/限流 → 停止外包，剩余自己做，如实告知；
  桥的重试设计（1 次重试 + 1 次跨 lane）是单任务上限，不是「再等等」的理由。
- **反例**：把「模型输出复述了错误关键字」型失败继续重试——同样的话术还会再触发。
- **关联**：SKILL.md「失败降级规则」；E-005

### E-010 调研类产出 = 模型已有知识，时效性内容必须标（待核实）
- **来源**：官方+实测（worker 无联网；DeepSeek 官方提示库亦要求对不确定内容声明）
- **适用场景**：T4 调研模板与一切涉及时效性事实（版本号、价格、发布时间、模型 id）的输出
- **要点**：模板强制「时效性内容一律标注（待核实）」；ZCode 汇总给用户前对关键事实自行检索
  核对（例如 2026-09 旧模型 id `deepseek-v4-flash` 下线这类变化，模型知识是滞后的）。
- **反例**：把调研初稿的版本号/价格直接当事实引用给用户。
- **关联**：原则 P8；模板 T4

### E-011 Cline App 的「free」标签 ≠ CLI 零成本，以 models 探测计价为准
- **来源**：实测（2026-09-25，用户 App 截图对照 + CLI 逐一探测）
- **适用场景**：选择 cline lane 模型、评估成本
- **要点**：App 标 "(free)" 的模型经 CLI 调用多数按量计费（DeepSeek V4.1 Flash ≈$0.001/次），
  仅个别目录级真免费（实测 `stealth/space-bunny-alpha` totalCost=0）。判定方法：
  `wbx models --as cline --probe "<vendor/model>"`（v5 起显示每次探测计价，$0 即免费）。
- **反例**：按 App 界面标签推断 CLI 成本；把 totalCost（名义计价）直接当作已扣款——
  免费额度机制（CLI 内含 FreeModelLimitResetTime）以账户侧实际扣减为准。
- **关联**：WBX.md v5 章调研记录 #13；原则 P8

## 沉淀闭环（经验 → 知识库的增量流程）

> 前提：`wbx history` 已落盘完整双向对话，可对「成功 job」做离线复盘抽取，不依赖会话记忆。

1. **谁做**：ZCode 以 T4（调研整理）/T5（结构化抽取）形态派发一个「复盘任务」，读取
   history 文件产出候选条目草稿；复盘者 ≠ 当事派发者，避免自证。ZCode 审查后入库。
2. **何时做**（任一触发）：
   - 成模触发：同类任务连续 3 次成功且话术高度相似 → 候选新模板；
   - 踩坑触发：同类失败 ≥2 次 → 候选反模式条目；
   - 官方变更触发：官方文档/模型目录变化（如旧模型 id 下线、新档位）→ 即时校订相关条目；
   - 周期触发：每累计约 50 个 job 做一次批量复盘（N 可按使用密度调整）。
3. **入库四标准**（四条全中才入库，未通过的直接丢弃，防知识库腐化）：
   - 可复现：≥3 次独立出现（或官方文档明示），非偶然；
   - 可迁移：换一个任务仍成立，不是一次性技巧；
   - 非显然：无法从既有模板/原则直接推出；
   - 可证伪：能写出明确的反例边界。
4. **落盘**：新模板入模板库并更新速查表；新经验按统一格式（编号/来源/适用场景/要点/反例/
   关联）入 E-xxx；文件头注明版本与日期。
5. **校订**：官方文档变更或新实测推翻旧条目时，直接修订原条目并更新来源日期，不叠加勘误。

## 派发流程（编排器视角，v5）

1. **判定**：任务自包含（输入可打包、输出可校验）→ 默认分派（单个也派）；涉密/探索式
   多轮 → 自己做。关键产物（关键代码模块/文案）→ 走 T8 双份。
2. **拆分与契约**：接口清晰的模块才可外包；ZCode 先写好接口契约（签名、类型、错误约定、
   验收标准）。
3. **备料**：读相关文件；按模板组装提示词（材料全文或按信噪比裁剪）；fanout 任务可直接写
   `"files": [...]` 让桥拼材料。
4. **分派**：≤3 个任务用 `ask --file`，≥3 个用 `fanout`；effort 按 v5 上调档
   （简单 medium、代码 high）；≥6 任务或结果很长 → 用 ZCode 自己的子代理管理整批，
   主上下文只收摘要（层级 ≤2）。
5. **校验**：逐份审查输出（围栏外夹带、完整性、编造 API/TODO）；代码模块集成前默认过一道
   T7 评审批判；保存为文件后编译/运行验收（集成、修 bug 由 ZCode 做，**每文件单一写者**：
   落盘后该文件归 ZCode 管）。发现问题 → T9 定向修复。
6. **止损**：连续 ≥2 个任务失败或限流 → 停止外包，剩余自己写，如实告知用户。
